> 判定口径：**✅ 已实现**（有独立机制/落库/UI，不依赖人肉）；**⚠️ 部分实现**（仅 prompt 级、或能力存在但未接线/不可调）；**❌ 未实现**（全仓无对应代码）

项目做的是一个**质量导向的多智能体创作引擎**，不是一个**增长导向的网文工厂**。

## 关键判断

1. **项目的定位不是「网文流水线」**。README 明确写着「与生成内容的 AI 写作助手不同，砚舟 通过追踪所有叙事元素，帮助作家保持故事的一致性」—— 方法论后半段（留存/付费/A-B/有声/短剧）属于**平台方**的活，不在本工具的射程内。这 14 项空白**不构成缺陷**，但**是产品边界**。

2. **真正的短板在「生成参数」与「去AI化」**（五、八类，合计 16 项只有 3 项完整）。这两块是**方法论里唯一"纯工具侧"却做薄了的部分**：
   - `temperature` 硬编码在代码里，作者无法按章节调（对话章节该高、设定章节该低）
   - 无 `top_p`/`frequency_penalty` —— 而「车轱辘话」「AI 味」正是这两项的靶子
   - 无 few-shot 范文 —— 「读者画像与圈层定位」「风格对齐」因此都没有抓手
   - 无去AI化后处理 —— 本项目靠**多角色门禁**保证质量，而非**后处理**，路线不同但代价是「AI 味」无处治理

3. **叙事技巧（七类 1/15）几乎全空**，但其中大半（爽点/打脸/信息差）是**题材套路**而非通用写作能力。项目选择了「让角色讨论出结论」而不是「套模板」，这条路线本身自洽 —— 只是意味着**它写不出爆款网文的爽感节奏**，写的是「讲得通的故事」。

4. **最强的三块**（九 多智能体 7/8、三 角色系统 4/6、六 记忆管理 4/8）恰好是**工程难度最高**的三块。这说明投入方向是对的：难的地方做扎实了，容易的地方（调参数、加后处理）随时能补。

## 如果要补，优先级建议

| 优先级 | 事项 | 成本 | 收益 |
|---|---|---|---|
| P0 | 暴露 `temperature`/`top_p`/`frequency_penalty` 到 AI 设置面板 | 低（`provider-factory.ts` 加字段 + UI 加控件） | 直接治「AI 味」与重复用词 |
| P1 | 参考书范文 few-shot 注入（把 `reference_books` 已抓的样本真正喂进 prompt） | 中 | 补上「风格对齐/读者定位」的抓手，数据已存在只是没接线 |
| P1 | 去AI化后处理门（困惑度/句长方差/对话占比） | 中 | 与现有三道门互补，不依赖模型自觉 |
| P2 | Token 消耗统计（`usage` 落库） | 低 | 长跑场景的成本可见性，现在完全黑盒 |
| P2 | 敏感词/合规扫描（发布前） | 中 | 十类里唯一有「法律风险」性质的缺口 |
| P3 | 同章多版本打分择优（`n` + 评分模型） | 高（调用量 ×3） | 质量上限提升，但成本敏感 |
